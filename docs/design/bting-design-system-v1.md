# B听视觉与交互规范 v1.1

日期：2026-10-24。适用项目：Blisten；应用：B听；口号：闭上眼听 B 站。

用户已选择 B「闭眼听友」，并认可整体界面方向。本规范将其固化为后续页面和功能共用的设计基线。**正式品牌资产、深浅主题及本版交互修正已落地。** 实际通过项与平台边界见[实施测试记录](../testing/2026-10-24-bting-design.md)。文中的“应”仍是后续开发基线，不代表所有设备、辅助服务和未来页面都已验收。

## 1. 用一句话理解

让用户容易找到想听的内容、开始播放，并在少看屏幕的情况下继续收听。整体温暖、安静、清楚；重要操作明显，反馈真实。

设计系统就是应用的“装修规范和操作约定”：以后新增一个页面，继续使用这里的颜色、字体、按钮和错误提示，无需重新选一套风格。本版覆盖现有功能及常规扩展；新业务仍需补充自身流程。

### 本文与其他文件的关系

- 本文是生效的视觉与交互基线；[新增功能设计单](new-feature-design-template.md)用于后续扩展。
- [B 品牌概念图](bting-v1/b-companion.png)和[整体 UI 概念图](bting-v1/b-ui-preview.png)是风格参考；图片里的示例资源、尺寸、卡片列数不作为功能或布局的唯一依据。
- [原始提案](bting-v1/b-ui-direction.md)保留讨论过程，与本文不一致时以本文为准。对既有业务的描述以代码及测试为事实依据，不用一张效果图推断功能。

| 项目 | 规则 |
| --- | --- |

| 口号 | 闭上眼听 B 站；主要出现在开屏和关于页，不重复占用每页空间 |
| 角色 | 奶油白 B 形身体、闭眼表情、珊瑚粉耳机、少量青色细节；保留 B 方案识别特征 |
| 使用位置 | 应用图标、启动、空状态、关于页；正常列表与播放器以真实资源封面为主 |
| 图标系统 | 页面控件沿用统一的圆角图标系列；同一动作使用同一图标和名称 |

## 3. 颜色：按用途取色

以下是本版采用的基线色值，延续已认可的 B 风格，由现有 `AppTheme` 统一提供。页面按用途读取，Material 主题与自绘控件共用；后续新增页面同样遵守。无需另建一套主题框架。

| 语义名称 | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| background | `#152342` | `#FFF8ED` | 页面背景 |
| surface | `#203252` | `#FFFFFF` | 卡片、底栏、弹窗 |
| surfaceHigh | `#2B4061` | `#F4EBDD` | 输入框、次级容器 |
| textMain | `#FFF4DE` | `#152342` | 标题、正文 |
| textSub | `#BBC6DC` | `#53617A` | 次要说明 |
| textHint | `#BBC6DC` | `#5E6A7D` | 输入提示、辅助内容；不额外降低正常文字透明度 |
| primaryFill | `#F58F9C` | `#F58F9C` | 主按钮、主播放控制 |
| onPrimary | `#152342` | `#152342` | 粉色按钮上的文字或图标 |
| actionText | `#F58F9C` | `#AC4157` | 可点击文字、选中标签、进度强调 |
| accentDecorative | `#8BD8D8` | `#8BD8D8` | 少量装饰；不直接用作浅底上的正文或唯一状态标识 |
| outline | `#899BB7` | `#6C788B` | 需要清楚识别的输入框/控件边界、焦点 |
| divider | `#344761` | `#DFD6CA` | 纯装饰分隔，不承担唯一的控件边界或状态表达 |
| success | `#8ED1B2` | `#216846` | 成功文字/图标，伴随明确说明 |
| warning | `#F0C36A` | `#805400` | 警告文字/图标 |
| error | `#FFADB3` | `#B52B43` | 错误文字/图标；不与品牌粉混为同一状态 |

主按钮可保留粉色，但浅色页面的小字、选中图标使用更深的 `actionText`。背景、边框和文字共同表示选中状态。禁用态可降低强调程度，但原因需要可获取；不能把透明度降低当作所有次要文字的处理方式。

49 组不透明色值组合已按相对亮度公式核算：[色板核算记录](palette-check-v1.json)。文字组合最低约 4.63:1，必要边界最低约 3.70:1，主按钮文字约 6.88:1。这仅验证设计色值，不代表应用实测通过；透明叠加、封面背景、渐变和系统控件需在实现后另验。

## 4. 字体、尺寸、布局与动效

| 项目 | 基线 |
| --- | --- |
| 字体 | 系统中文无衬线字体；正文不用装饰字，不新增必需字体下载 |
| 字号层级 | 页面标题 24、区块标题 20、主要正文 16、次要内容 14、辅助标签 12；按逻辑尺寸设计并支持系统文字缩放 |
| 字重 | 正文常规；标题/主要操作中等或半粗；同一层级一致 |
| 间距 | 使用 4、8、12、16、24、32 的尺度；页面侧边通常 16，区块间通常 24 |
| 圆角 | 小控件 12、卡片/输入框 16、底部面板上角 24；模式标签可用胶囊形 |
| 点击区域 | 普通交互至少 48×48 dp；主播放控制通常 64～72 dp。可见图标可以更小，但点击区域不能跟着缩小 |
| 层次 | 靠背景色、间距、边界分层；少用重阴影、光晕和大面积渐变 |
| 封面 | 保留资源图片；缺图/加载失败有统一占位，不用吉祥物替换所有正常封面 |
| 小屏与大字 | 不固定文字容器高度导致截字；标题可换行或省略并在详情可读全；主操作始终可达 |
| 网格 | 以现有布局为基础；窄屏或放大字体时可降低列数/纵向排列以避免溢出，不新增布局设置开关 |
| 动效 | 普通反馈短而克制，建议 150～250 ms；尊重减少动效设置，无需持续旋转或闪烁来证明正在播放 |
| 启动 | 系统启动图与应用开屏一致，初始化完成就进入应用，不为品牌展示添加固定等待 |

保留“跟随系统 / 浅色 / 深色”，默认跟随系统。播放与切换主题互不干扰；返回、打开键盘、系统栏和底部安全区域均需正确处理。本版先验收 Android 手机；平板和 Windows 专门布局不因此自动成为承诺。

## 5. 共用组件与行为

| 组件 | 外观与动作约定 | 必须考虑的状态 |
| --- | --- | --- |
| 主/次按钮 | 每个操作区域突出一个主动作；提交中反馈在原位置，不重复提交 | 正常、按下、聚焦、禁用、加载 |
| 模式标签 | 名称固定；文字和形状共同表示选中；页面切换模式不静默修改已有资源类型 | 选中、未选中、不可用 |
| 资源卡片 | 封面、标题、模式及必要进度；同一上下文的点击结果一致 | 正常、缺图、已收藏、播放中、无法加载 |
| 搜索/输入框 | 有输入用途说明；错误贴近字段；失败保留输入，给出可执行修正 | 空输入、输入中、校验失败、提交中 |
| 迷你播放条 | 显示实际播放会话；点主体打开播放器，播放按钮只控制播放 | 播放、暂停、缓冲、失败；无会话时隐藏 |
| 进度条 | 拖动位置可读，提交后与播放器实际状态同步；未知时长不伪造进度 | 可拖动、加载中、时长未知、播放结束 |
| 底部面板 | 倍速、定时、目录等同类轻操作使用一致布局；系统返回先关闭面板 | 正常、选中、提交失败 |
| 提示条 | 成功/一般反馈简短，不挡主要操作；重要失败不能只闪一下就消失 | 成功、一般提醒、可重试失败 |
| 确认弹窗 | 用于有数据损失的操作，说明对象和后果；明确“取消”和具体动作 | 待确认、执行中、执行失败 |
| 空/错误状态 | 状态标题、简短原因、下一步；默认最多两个动作，不堆满入口 | 初次空白、无结果、加载失败、暂无权限 |

组件优先在现有 Flutter Material 组件和 `lib/widgets/` 上统一样式。只有确实重复的模式才提取共用组件，不为了“规范完整”创建当前没有用途的控件库。

## 6. 页面职责与关键路径

### 导航

- 收藏：用户保存的内容，以及继续打开已有资源的入口。
- 发现：按听书/听歌/听现场查找内容；提供搜索和链接导入。
- 我的：登录相关入口、最近收听、缓存、定时、外观、设置、关于等现有工具。
- 详情与播放器是后续页面，不增设新的底部主标签。返回先关闭键盘/面板，再返回上一层；播放器返回通常继续播放，不能与暂停混淆。
- 保留已有标签页面状态。返回提示必须描述真实目的地，例如“返回上一页”，不保证必定返回发现页。

### 找内容 → 播放

选择模式 → 搜索 → 资源详情 → 开始播放或选择某一分 P → 播放器。筛选、结果和单位与模式一致；搜索与导入失败不清空用户输入。是否收藏遵守既有模式规则，不能由视觉改版偷偷改变。

### 搜索分类与 UP 主页

搜索页使用一层并列分类：“听书 / 听歌 / 听现场 / UP 主”，搜索前后均可选择。前三项对应听书、歌曲、演唱会；UP 主是找创作者的入口，不是第四种播放模式。切换保留输入，已搜索时立即重查；失败保留当前分类并提供重试，不回退成旧分类的结果。

UP 搜索独立查询用户，共用搜索历史，不套用某一内容类型的热门词。列表分页失败保留已加载内容，尾部提供持续可见的重试按钮，避免滚动期间反复发失败请求。进入 UP 主页时默认沿用搜索页最近内容模式，并显示可切换的三模式；模式改变后重载第一页，详情、分页和空态搜索均沿用当前模式。

四分类复用 ChoiceChip，大字窄屏允许换行；一次只选中一个，读屏提供选中状态。具体流程见[搜索分类设计](../superpowers/specs/2026-10-24-search-categories-design.md)。

### 粘贴链接 → 添加

主动打开导入 → 粘贴 BV/视频链接/分享文本/短链接 → 确认类型 → 解析校验 → 添加到收藏 → 详情。默认类型沿用当前模式，提交前可见且可改；不要仅凭标题静默推断。解析错误留在表单，提供重试或修正输入；仅在用户主动粘贴时读取剪贴板，不把后台监听加入本次范围。

### 首次使用

无需强制教程或强制登录。空收藏解释“搜索或粘贴 B 站链接，添加想听的内容”，提供“去发现”和“粘贴链接 / BV号”。复用已有能力，不新增注册流程或新内容源。

### 播放中离开页面

返回收藏/发现/我的主页面后，用已有迷你播放条继续控制；搜索、详情、设置等其他页面延续现有入口，本次不扩展成所有页面常驻。锁屏/后台媒体控制显示真实标题与状态。拒绝通知权限后的行为需真实测试与说明，不能在设计图上假定所有控制都可用。

## 7. 播放与数据的既有约定

以下为本版保持的播放约定；实际播放与跨进程回归结果见[实施测试记录](../testing/2026-10-24-bting-design.md)。

| 操作 | 听书 / 听现场 | 听歌 |
| --- | --- | --- |
| 首次倍速 | 1.0×；听书兼容旧倍速设置 | 1.0× |
| 调整倍速 | 按模式独立记忆，0.5～3.0×；不按每部作品单独保存 | 同左 |
| 从收藏/现有最近收听重新选择资源 | 恢复最后分 P 和时间 | 首个分 P 从 0 开始 |
| 详情目录/播放器明确选择某一分 P | 所选分 P 从 0 开始 | 同左 |
| 点击某条缓存 | 若恰为最后收听分 P 则恢复时间，否则从 0 开始 | 所选分 P 从 0 开始 |
| 暂停后继续 | 当前分 P 和时间继续 | 同左 |
| 打开已有播放会话页面 | 只打开播放器，不重新加载 | 同左 |

- 断点按 BV 资源保存，不为三个模式分别存三份；按模式区分的是倍速与恢复规则。
- 听书有约一分钟播放后自动收藏及缓存入口自动收藏；歌曲与演唱会不套用该规则。视觉改版不引入新的自动收藏策略。
- “最近收听”当前只展示已收藏且保存位置大于 0 的条目；底层也保存有限数量的未收藏断点。不能把现有列表宣传为完整历史记录。
- 定时到点暂停；“播完当前章/曲/段”阻止继续下一 P。倒计时在暂停时仍计时，定时状态目前不跨进程恢复，不承诺重启后继续倒计时。
- 删除缓存不删除收藏和断点；移出收藏会清除该 BV 的收藏及最近断点，不删除缓存。继续播放可能再次写入断点，不能声称永久删除全部历史。
- 移出收藏的每个入口应在执行前说明进度也会清除。详情与收藏页已复用同一确认流程。
- 不包含跨视频歌单、随机/循环、自动分曲、歌词或直播。以后新增时使用设计单补充流程，不把概念图里的装饰当成功能。

核验入口：[模式](../../lib/models/content_mode.dart)、[倍速](../../lib/player/playback_preferences.dart)、[播放器](../../lib/player/book_player.dart)、[收藏/断点](../../lib/core/storage/shelf_store.dart)、[模式回归](../../integration_test/audio_modes_test.dart)。

## 8. 状态与异常：不能只设计正常页面

| 状态 | 用户应看到什么 | 操作与数据规则 |
| --- | --- | --- |
| 首次空收藏 | 为什么为空、可以怎么添加 | 去发现 / 粘贴链接；不伪造推荐数据 |
| 搜索无结果 | “没有找到相关内容”等中性说明 | 修改关键词或重新搜索；保留输入与模式 |
| 请求加载中 | 操作位置的进度反馈 | 不伪造百分比；不要重复提交；失败/超时可恢复操作 |
| 刷新/分页失败 | 已有内容与局部错误 | 保留列表，局部重试；不把整页变成空白 |
| 网络或接口失败 | “加载失败，请重试”等可证实描述 | 保留输入/收藏；仅在已知有缓存时提供缓存入口 |
| 暂时无法播放 | 明确播放失败，说明可采取的下一步 | 重试或返回；有可用缓存时提供实际缓存路径；不自动移除收藏 |
| 确认资源不可用 | 与可靠返回信息一致的说明 | 如建议移出收藏，告知进度清除并让用户选择 |
| 未登录/登录失效 | 当前功能是否需要登录、如何登录 | 不阻断不依赖登录的流程；二维码失败/过期能刷新，不无限无声等待 |
| 权限拒绝 | 说明哪项能力受影响 | 请求发生在相关操作时；保留不依赖该权限的功能，不重复强迫弹窗 |
| 缓存失败/空间不足 | 哪项失败及可操作原因 | 失败任务可重试或移除，不把失败显示为缓存成功 |
| 删除操作 | 被删除对象、连带影响 | 影响数据的操作确认后执行；失败保留原状态并反馈，不先宣称成功 |

后端错误、网络断开、登录过期和资源下架需要区分。无法可靠分类时使用中性文案，详细诊断留在日志；不要把堆栈或内部异常直接作为面向用户的唯一解释。

## 9. 可读、可点、可辅助操作

- 正常文字组合以至少 4.5:1 为项目目标；必要的控件边界/状态标识至少 3:1。封面上文字必须有足够遮罩，不能假定任意图片都适合白字。
- 普通触控目标至少 48×48 dp；图标按钮有可理解的动作描述，播放/暂停描述随状态变化。
- 支持系统文字放大；检查中文长标题、200% 文字缩放、320 dp 窄屏。以上是本项目检查点，不能用通过某一个尺寸代替完整适配结论。
- 用 Android TalkBack 检查主要路径和焦点顺序；装饰图不重复朗读，拖动进度和状态反馈可被理解。
- 不只靠颜色表示选中/错误；减少动效时保持操作反馈但去掉非必要运动。

触控与文字原则参考 [Android 无障碍指南](https://developer.android.com/guide/topics/ui/accessibility/apps)，读屏与缩放检查参考 [Flutter 无障碍清单](https://docs.flutter.dev/ui/accessibility)。对比度计算参考 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；这些资料用于质量目标，不表示本应用已获得认证或完成全部验证。

## 10. v1 实施内容与验收顺序

### 第一批：正式资产与统一主题

从已选 B 概念生成干净的独立角色/透明前景，保留模型原图及提示词；制作 Android 自适应图标、常规图标与启动资源，统一 `assets/logo.png`。生图负责艺术资产和视觉参考，实际页面文字、布局与交互由 Flutter 实现，不把整张生成图当作界面。

调整现有主题与控件；覆盖收藏、发现、我的、播放器/迷你条、详情、搜索/导入、缓存/定时/登录/设置等现有页面，以及明暗两套外观。启动页已同步统一背景与品牌资源。Windows 图标已使用同源母版；实际 Windows 构建必须另验，不冒称本机已验收。

### 第二批：已修正的状态与提醒差距

| 现有差距 | 入口 | 预期修正 |

### 第三批：验证与交付

1. 将正式图标、启动页、正常/空/失败态保存为实测截图，标明模拟器、主题、文字缩放与样例数据；与概念图分开。
2. 检查深浅色、小屏、大字、键盘遮挡、点击区域和读屏；测实际叠加后的色彩，补必要的组件行为检查。
3. 运行现有 `tool/test-android.sh unit`；涉及播放器、数据或 Android 原生资源时运行专用模拟器回归。接口未改时不将联网测试作为视觉改动的必需条件。
4. 新增交互修正应验证原症状和失败恢复，不写仅重复颜色常量的无意义测试。需要视觉快照时固定字体、环境和数据，限定关键组件。
5. 记录实际通过、失败与未验收范围。此阶段不自动创建签名、四种正式 APK 或远程发布。

## 11. 后续功能如何保持一致

每项新增功能填写[设计单](new-feature-design-template.md)，先说明它帮助用户完成什么、放在哪里、复用哪些组件、有哪些失败状态，再实现。普通可逆选择按规范执行，不要求用户逐个选择圆角、间距或按钮颜色。

复用已有规则即可完成时，无需添加新设计概念。确有新组件时，先在这份规范中补用途、状态和实例，再供页面复用。已有页面继续遵循同一规则，避免每个功能各自造一套按钮。

涉及品牌方向、底部导航、播放/删除规则、数据迁移、权限或发布范围的变化，应说明原因、影响及与当前版本的区别，并按用户授权决定。不能以“更好看”为理由隐藏业务变化。

开发前由 `AGENTS.md` 和 `CONTRIBUTING.md` 指向本文；PR 说明使用的规范版本、界面变化及深浅色验证。设计新增资产继续使用生图模型并保存提示词；代码原生的按钮、布局、文本不需要逐个生成图片。
