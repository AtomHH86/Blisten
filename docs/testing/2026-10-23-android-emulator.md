初装的 Emulator 37.2.12 在本机播放时发生 CoreAudio 锁等待，最终由 HangDetector 结束进程。堆栈与[对应版本的官方源码](https://android.googlesource.com/platform/external/qemu/+/bbaa8072362a251645b339b97a737a725c776126/audio/coreaudio.c)一致。将模拟器单独固定为 36.5.11 后继续实跑；安装脚本核验官方 SHA-256，旧版二进制及诊断留在工具链目录。这项结论限于本机和实测版本。

36.5.11 的窗口模式曾出现 `EGL_BAD_NATIVE_WINDOW` 和首段播放超时。本机最终采用无窗口自动回归，保持系统、音频和图形配置不变后，主套件约 30 秒通过。采样没有再次发现 CoreAudio 锁死；由于对照也包含模拟器进程重启，不能将全部性能差异归因于窗口。

## 本次发现与修复

缓存队列在新增任务、重新持久化时，会把正在下载的任务重建为缺少 `page`、`part`、`order` 的记录。回归测试先复现第 3 P 被保存为第 0 P，再用 5 行改动保留完整活动请求，避免重启后丢失分 P 排序信息。没有调整三种模式的业务规则。

测试运行器额外处理了两个框架行为：使用 `flutter drive --keep-app-running` 避免每次集成测试结束卸载包，显式结束进程验证持久化；将初始化和清理钩子的异常、超时写入 driver 读取的失败结果。初始化允许 90 秒，其余钩子 25 秒，整体 driver 上限 10 分钟。三个故意失败场景都返回 1，见[负向验证证据](evidence/2026-10-23-harness-failures.json)。

原生 UI 自动化还明确等待页面动画完成，限定当前页面内的按钮；导入错误重试时重新聚焦输入框，断言新链接已实际写入，等真实键盘展开并稳定后再关闭，视口稳定后提交。暂停控制则等待最后一次异步进度通知稳定，再验证进度不再增加。

## 验证边界

- 默认回归中的 B 站接口使用固定响应，音频为本地 HTTPS 服务提供的静音 WAV；播放器、缓存文件、Android 存储和媒体处理器使用真实实现，TLS 校验保持开启。
- 离线播放用例关闭测试 API 和音频服务的可用性，再从缓存页播放本地文件；不是切换系统飞行模式的测试。
- 跨进程恢复是保存完成后结束进程，再启动新进程核对数据；不代表突然断电或写入中断已验证。
- 真实 B 站联网冒烟独立执行；不保证未来平台接口或资源始终可用。没有进行电脑扬声器的主观音质验收。
- 尚未覆盖最低 Android 7 系统、其他 ABI 的运行、16 KiB 内存页、直接点击系统通知栏、蓝牙和电话打断、厂商省电策略及长时间后台播放。正式发布前仍需相应兼容性与安装升级验证。

## 四种正式 APK 的交付方式

`tool/build-android-apks.sh` 分别构建 ARM64、ARMv7、x86_64、universal，保持同一 `versionCode`，对实际 ABI、原生库、最低系统、包名、版本、非调试签名和证书一致性进行核验，然后输出 `manifest.json` 和 `SHA256SUMS`。缺少正式证书时会在构建前退出；不会静默用调试证书交付。

本次已验证打包脚本的解析与拒绝路径，并核对真实 Gradle ABI 配置。没有正式签名配置，因此四包实际 release 构建、安装、覆盖升级尚未执行。原先 26 / 23 / 28 / 73 MB 只是估计，正式文件大小须以产物清单为准；universal 仅包含上述三种 ABI。
