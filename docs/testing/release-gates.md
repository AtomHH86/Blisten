# B听发布前验收门槛

此记录区分已验证的代码行为与正式发布尚缺的证据。未生成正式签名包，未配置远程仓库或执行远程 CI。应用版本仍为 1.0.0+1。最终状态见[质量修复验收记录](2026-10-24-quality-repairs.md)。

## 签名与四包

正式打包仍由用户另行确认。使用项目打包脚本，不把 debug证书的release构建当正式包。签名私钥、密码、key.properties不入Git、日志或bundle。

1. 创建或选择长期使用的签名证书，记录公开证书SHA-256、别名和恢复负责人；密码单独保存。
2. 将私钥和所需配置存入两份受控离线备份；恢复到独立安全位置并核对证书摘要，完成一次实际签名验证后再认定备份可用。
3. 同步pubspec.yaml与app_meta版本，versionCode递增。用正式脚本分别生成ARM64/ARMv7/x86_64/universal，记录真实大小、ABI、包名、版本、签名、SHA-256和16KiB静态报告。
4. 首次安装与覆盖升级均用候选包验证。B听包名与原阿B听书不同，不覆盖原应用；debug也与正式版独立。
5. 升级测试以合成收藏/设置/进度/缓存为样本，验证旧凭据迁移、收藏目录/模式、取消收藏标记、缓存索引与登录状态。不要对真实用户数据执行pm clear或卸载。
6. 回滚优先采用旧代码修复后提高versionCode、保持签名的新包，并测试新数据的兼容读取；不要把adb强制降级当用户回滚方案。卸载会删除应用私有数据，源码Git恢复不恢复用户手机数据。

本轮新增字段均兼容缺省旧数据；Cookie迁移后旧程序未必能读取隔离存储，应允许重新登录，不把账号会话放入导出/备份作为回滚手段。正式APK安装/覆盖升级/回滚数据演练仍待验。

## 依赖与对外入口

[本轮依赖审计](../reviews/2026-10-24-dependencies/README.md)已保存锁文件清单、观察到的 debug Maven 图、传递许可证候选、音频原生库来源和公告适用性。原生库版本匹配及来源/许可缺口使正式发布门槛仍未通过，需下一轮升级/替换评估、编译功能与可达性核对、补完整通知/源码材料及实际 release 图。当前调查中发现的缺口不能被单元测试通过覆盖。未配置的反馈/更新入口继续明确显示未配置，发布前补可用地址并验证。

日常本机回归、独立联网检查、备份隔离与原生寿命检查的命令见[电脑测试指南](android-desktop-guide.md)。线上B站资源和平台限制变化独立于确定性回归。

16KiB 静态规则依据 [Android 官方兼容说明](https://developer.android.com/guide/practices/page-sizes)与[原生库提取属性](https://developer.android.com/guide/topics/manifest/application-element#extractNativeLibs)：检查全部装载段和只读段的实际布局；直接 APK 加载检查存储偏移，安装时提取则检查提取后 ELF 条件。实际设备运行仍是独立门槛。CI Java 固定为 17 主版本，补丁版本随 runner 镜像变化；Flutter 固定版本和提交，不能称整个环境逐字节可复现。
